## 遗留问题

- **A8（相机被占用）未实测**。已排除的自动化路线（都实测过，不是猜的）：
  1. 「系统相机前台 → 切到本应用」**不行**：切后台时系统相机会释放摄像头
     （hilog `com.huawei.hmos.camera/SessionWrap: session stop error: {"code":7400201,...}`），
     本应用随后能正常打开相机（`准备就绪 · JPEG 4160x3120`）。
  2. `aa start -W --wl/--wt/--ww/--wh` 放浮动窗**不行**：窗口参数在 Stage 模型下无效（`-s` 标注 only for FA mode）。
  3. 分屏（智慧多窗）只能靠手势/拖拽，`uitest` 没有稳定路径。

  4. ~~分屏~~ **已排除**：用户实测**系统相机不支持分屏**（智慧多窗里放不进去）。

  **人工补测步骤（推荐用「悬浮窗」，需要用户操作）**：
  1. 桌面打开系统「相机」→ 让它处于预览/录像状态（此时摄像头被它占着）；
  2. 把系统相机变成**悬浮窗**：上滑停顿进多任务 → 长按/点该应用卡片上的「悬浮窗」按钮
     （或把卡片拖到角落），确认相机预览在小窗里**仍在动**；
  3. 从桌面/程序坞打开「待删相机」（悬浮窗保持在最上层，摄像头仍被它占着）；
  4. 点「打开相机（拍照）」；
  5. **预期**：显示 `相机启动失败：<code> <message>`，**不闪退**；
     把悬浮窗关掉后再点一次「打开相机（拍照）」，应能恢复正常预览（可重试）。

  把第 5 步的原文发回来即可作为 A8 证据。若悬浮窗也被相机禁用，则 A8 记为
  「设备上无法构造并发占用」——**如实记为未验**，不写通过。
- **A7 / A10 只有 L1 等价证据**：CLI 无法安全构造（改系统时间 / 写满存储），已在
  `docs/ACCEPTANCE-REPORT.md` 如实标注为「仅 L1 覆盖」，**不算真机通过**。
- ~~**性能基线未做**~~ → **待删除页 1000 张已实测（2026-09-11）**：
  - 造数：新增 `seedBulkPending`（固定 320x240，**修掉了原 `seedDemoPending` 的 `320+i*40` 递增尺寸**——
    1000 条时最后一张宽 40280 px，会把设备拖垮），1000 条真实 JPEG + 1000 张缩略图，总耗时 **66045 ms**；
  - 首屏：打开待删除页 **36 ms**（`hilog: trashLoad: items=1000 ms=36`），汇总 `1000 张 · 共 1.2 MB`；
    页面开发区常驻回显「首屏加载 36 ms（1000 张）」（`hilog` 同理，便于回归对比）；
  - 拖动两次后页面与进程均正常（pid 不变）；
  - ⚠️ **未测的是滚动帧率**：36 ms 只含「物化 + 查询 + 状态写入」，不含逐帧渲染。**不写「不掉帧」**。
  - 连续拍摄 50 张的耗时/内存仍未采集。
- **桌面图标两次消失（已定位到「应用被系统静默卸载」，非本项目脚本所为，但根因未确定）**：
  - 实测事实：① `scripts/` 全量 grep **没有任何 uninstall**（`hdc uninstall` 只在人工步骤里用过一次，
    是为 A9 重置权限，之后已重装）；② 存储充足（158 GB 可用）；③ 调试 Profile 有效期
    **2026-09-11 → 2027-09-11**，未过期；④ 两次卸载分别发生在 `11:40` 与 `11:54:20`，
    后者可由 launcher 日志 `LauncherAbilityManagerBasic --> mBundleStatusCallback remove bundleName: com.dsh.photodelete` 精确到秒；
    卸载同一秒 `AppGallery`（`cancelDownload ... dlPkgName=com.dsh.photodelete`）、
    `aidataservice`（`publish PackageRemove`）、`parentcontrol`（`onChildRefreshPackageEvent`）都在活跃。
  - 对照实验：另外两次「装完就盯着」分别是**空闲 5.5 分钟**与**前台运行 7 分钟（含相机页）**都没被卸载
    ⇒ **不是固定定时器，也不是「一运行就被删」**。
  - **第三次（12:15:24）抓到了调用链的一段**：`com.huawei.hmsapp.appgallery` 的
    `@hw-ae-business/download-install` → `PackageEventSubscriber.processPackageRemoveCallback`
    → `UpgradeManagerWrapper.onPackageRemove` —— **应用市场的「下载安装/升级」模块在处理这次移除**；
    同时 `foundation/BMSInstaller: CheckUninstallDisposedRule`、`AppMS: reason=UninstallApp` 确认走了 BMS 卸载接口，
    进程被系统杀掉（`PROCESS_KILL ... reason=UninstallApp`）。
  - 结论：**能确定「不是本项目工具链干的」，且卸载来自系统 BMS 接口、与应用市场的安装/升级模块相关；
    但具体触发条件仍未确定**（缓冲区丢过日志，无法指认发起者 uid/bundle）。
    处理办法见 `docs/ENVIRONMENT.md` §8 的新条目（用户侧开关 + 快速自检命令）。
  - **待用户确认的设备侧检查项（按可能性排序）**：① 应用市场 → 我的 → 安装管理/下载任务，是否有「待删相机」残留任务；
    ② 应用市场设置里的自动更新/安全检测；③ 设置 → 系统和更新 → 纯净模式（若有则关闭）；
    ④ 设置 → 健康使用平板/家长控制是否限制了未知来源应用。
