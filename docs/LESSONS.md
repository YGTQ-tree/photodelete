# 经验总结（LESSONS）：遇到"做不了"时，先把资料和前人经验查透

> 本文件是**方法论**记录，不是功能说明。触发它的是本项目连续三次误判与更正 —— 全部发生在"平台能力边界"这类问题上。
> 结论一句话：**「做不到」和「做得到」都必须有证据；证据来自「SDK + 官方文档/前人经验 + 真机实测」三处，缺一处就可能错。**

## 一、三次真实误判（都记下来，避免下次重犯）

| # | 我当时的结论 | 依据 | 实际情况 | 是什么救回来的 |
|---|---|---|---|---|
| 1 | "三方应用无法实现应用内截屏" | 只扫了 `@ohos.window` / `AVScreenCapture`（都要系统权限） | **错**。SDK 里有 `@ohos.screenshot`，其中 `pick()` **无 `@permission`**，返回 `PickInfo{pickRect, pixelMap}` | **用户要求"再检查下"**，我才去 `ls api \| grep screen` 找到该模块 |
| 2 | "`CUSTOM_SCREEN_CAPTURE` 是受限权限，要 AGC 审批" | 望文生义（和 `WRITE_IMAGEVIDEO` 归为一类） | **错**。它是 **`user_grant`**（弹窗授权即可）、API 14+、仅平板/2in1 | **搜索前人实战文章**（[掘金：截屏权限 CUSTOM_SCREEN_CAPTURE](https://juejin.cn/post/7670111026742640650)），学到查/申请要用两个不同函数等一整套经验 |
| 3 | "能不能删除系统图库照片？" | SDK 注释：`deleteAssets` 需 `WRITE_IMAGEVIDEO` | **确实是"不能"（但必须有旁证才敢下结论）** | 继续搜到**真实审核被拒案例**（AGC 审核意见「暂不支持图片删除功能」）+ 官方答复"引导用户在系统图库内删除" ⇒ 才敢判定为平台禁止 |

关键对照：**#1/#2 是"误判成不能"，#3 是"核实后确认不能"**。同样是"做不到"的结论，一个有据、一个无据 —— 区别只在有没有把资料查透。

## 二、可复用的查证顺序（按成本从低到高）

1. **扫 SDK**（最快、最权威的"接口存在性"）：
   ```sh
   ls $SDK/api | grep -i <关键词>              # 有没有这个模块
   grep -n "@permission\|@since\|@systemapi\|@throws" <模块>.d.ts   # 谁需要权限、从哪个版本、会抛什么
   ```
   ⚠️ 特别注意 `@throws 801 Capability not supported on this device` —— 它意味着**"接口存在"≠"设备支持"**。
2. **查官方文档 + 前人经验**（决定"能不能拿到、怎么拿"）：华为开发者论坛问答、掘金/CSDN 实战连载、itying 等存档站。
   优先找**带审核结果/真机现象**的帖子——那类信息最有价值（例：#3 的审核意见原文）。
3. **真机实测**（唯一能推翻前两步的东西）：本项目的 `801`（pick 在平板上不支持）、`201`（删除图库被拒）、
   `batch export: ok=7 fail=0`（一次授权覆盖多次写入）都是这一步量出来的。
4. **对照实验定位根因**，不要用"机制推测"：
   - A5 缺陷：我先按"Proxy 理论"写了注释和测试 → **真机一测就被否掉**；改用 A/B 探针（直传 vs 复制）才定位到
     "`@State` 数组不能直接进 native `predicates.in()`"。
   - 预览扭曲：先按"铺满更好看"做了 cover → 真机分屏截图证明平台会把 surface 缩放到可见区域，回退 letterbox。
5. **每条结论标注证据等级**：`文档事实` / `实测事实（命令+输出）` / `推断（待验证）`。
   例：手机端 `pick()` 可用目前只是**推断**（手上只有平板）——报告里必须这么写，不能写成事实。

## 三、结论会变，要留更正记录

- 本仓库已有两处公开更正：`docs/LIMITATIONS.md` 里"CUSTOM_SCREEN_CAPTURE 非受限权限"、
  以及"三方不能截屏"的推翻。**更正要写进文档而不是悄悄改掉**，否则下一个人会重复踩坑。
- 每个"做不到"的结论都要附**替代方案**（平台禁止删除图库 → 引导用户去图库删 / 批量导出；
  设备不支持 pick → `window.snapshot()` + 系统截屏 + 导入）。只写"不行"的结论等于没交付。

## 四、这次沉淀下来的两个具体成果

1. **截屏的三级路径**（运行时探测，不依赖机型/版本预判）：
   `capture()`（平板/2in1 + user_grant，已真机成功 2800×1840）
   → `pick()`（手机很可能支持，待手机实测）
   → `window.snapshot()`（含本页，任何设备可用）/ 系统截屏 + 应用内「导入」。
2. **照片"送出"的唯一正解**：由本应用用 `systemShare.ShareController` 发起分享（沙箱 uri 临时授权），
   而不是指望别的应用"从相册选择"能选到我们的沙箱文件（平台边界）。
