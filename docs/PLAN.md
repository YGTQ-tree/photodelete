# 项目计划：PhotoDelete（鸿蒙 6.1 原生）

> 执行者：DeepSeek Harness。行为约束以 [`AGENTS.md`](../AGENTS.md) 为准；本文负责「做什么、按什么顺序、什么算做完」。

## 0. 目标与非目标

**目标（最小闭环）**

1. 自研相机页：预览 + 快门 + 一个「N 小时后自动转入待删除」勾选项（时长可调，默认 24h）。
2. 到期自动整理：照片进入「待删除」相册，不依赖用户手动搬运。
3. 「待删除」页：网格浏览、多选、**一键删除**；删除前可「保留」撤销出队。
4. 设置页：默认时长（1h / 6h / 24h / 72h / 永久）。

**非目标（明确不做，避免范围蔓延）**

- 不做系统相册的清理器（平台不允许，见 §1.1）。
- 不做云同步、AI 分类、人脸识别。
- 不做截图自动纳管（二期，见 §6 与 T07）。
- 不做卓易通 / Android 版本（否决理由见附录 A）。

## 1. 决定架构的四个平台事实

### 1.1 三方应用删不掉系统相册的图（决定性）

`ohos.permission.READ_IMAGEVIDEO` / `WRITE_IMAGEVIDEO` 属**受限开放权限**，官方口径只对克隆、备份、同步类场景开放；有开发者提交「相册清理」类应用被审核驳回的实例。华为侧明确「谁创建，谁管理」：三方应用只能自由管理**自身创建**的媒体资源。
来源：[受限权限申请与相册删除能力问答](https://bbs.itying.com/topic/69bc3a3b6f4d61004c83f869)、[受限开发权限列表](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/restricted-permissions)。

**架构后果**：不做「清理系统相册」，改为**自有媒体仓**——相机出图直接落应用沙箱，元数据落本地 RDB，删除只删自己的文件。好处是零受限权限、零系统弹窗、删除永远成功；代价是照片不进系统图库（由应用自己的 UI 承担浏览职责）。

### 1.2 后台任务不保证准时

`workScheduler` 是延迟任务调度，受应用分组与系统配额约束，不能当作精确闹钟，也不保证被调用。
来源：[延迟任务(ArkTS)](https://developer.huawei.com/consumer/cn/doc/HarmonyOS-Guides/work-scheduler)。

**架构后果**：正确性由**惰性物化**保证——`normalize()` 在 App 启动、回前台、相机页退出时执行，纯函数 `expireAt <= now` 判定到期；`workScheduler` + 通知只做「尽量提前整理并提醒」的增强。这一条同时让应用在「被杀死/被限制」时依然行为正确。

### 1.3 相机出图落盘路径 —— ✅ 已由真机探针定死

曾是本计划唯一的技术未知数：`photoOutput` 出图后字节流如何落到应用沙箱。
**2026-09-11 在真机（TGR-W10 / HarmonyOS 6.1.0.135 / API 24）实测关闭**，结论见
[`ADR-001`](decisions/ADR-001-camera-capture-path.md)：采用 `photoOutput.on('photoAvailable')`
→ `Photo.main.getComponent(ComponentType.JPEG).byteBuffer` → `fileIo` 写沙箱，
**全程不申请任何媒体库权限**（架构前提在真机被证实）。
来源参考：[Camera Kit 预览、拍摄与保存管线实战](https://ost.51cto.com/posts/40489)。

### 1.4 目标版本（实测后的版本矩阵）

| 角色 | 版本 | 说明 |
|---|---|---|
| 真机 | HarmonyOS **6.1**（API 23） | 主验证目标；开发者模式已开 |
| 本机 SDK | `apiVersion = 22`（`6.0.2.130`） | 工具链 `6.0.2.670` 自带，`compileSdkVersion` 只能是 `"6.0.2(22)"` |
| 工程配置 | compile `6.0.2(22)` / target `6.0.2(22)` / compatible `6.0.0(20)` | 必须满足 `compatible ≤ target ≤ compile` |

来源：[HarmonyOS 6.1.0 (23) 占比数据](https://m.ithome.com/html/945550.htm)、[HarmonyOS 7.0 三个 SDK 版本字段详解](https://ost.51cto.com/posts/46857)。版本策略记录在 [`ADR-002`](decisions/ADR-002-toolchain-and-signing.md)，鸿蒙 7 适配记录在 [`ADR-003`](decisions/ADR-003-harmonyos7-adaptation.md)。

## 2. 核心设计决策（ADR 摘要）

| # | 决策 | 理由 | 代价 |
|---|---|---|---|
| D1 | 媒体资产存**应用沙箱**，不进系统媒体库 | 绕开受限权限；删除必然成功 | 照片不出现在系统图库；需自建浏览 UI |
| D2 | 到期判定是**纯函数**，物化是**惰性**的 | 不依赖后台调度，杀进程/重启后行为一致 | 用户必须打开过 App 才会看到整理结果（用通知补偿） |
| D3 | 领域层与鸿蒙 API **物理隔离**（纯 TS，可擦除语法） | SDK 未就绪时即可在 Node 上跑单测；80% 逻辑不依赖真机 | 需要 Clock/FileStore 依赖注入，多一层接口 |
| D4 | 每张照片**快照**拍摄时的时长策略 | 之后改全局设置不影响历史照片的到期时间 | 数据表多一列 JSON |
| D5 | 删除是**硬删**，但提供「保留」撤销 | 最小闭环；待删除只是视图，不是回收站 | 无回收站，误删不可恢复（一期接受） |
| D6 | `workScheduler` 只做增强，且只注册**一个**周期任务 | 避免配额被多任务摊薄 | 整理时机不确定，需要通知引导用户打开 App |

## 4. 验收标准（端到端场景）

| # | 场景 | 通过判据 |
|---|---|---|
| A1 | 拍摄并勾选 1h | 相机页拍摄后立刻在「缓冲」可见；记录的 `expireAt ≈ capturedAt + 1h` |
| A2 | 不勾选拍摄 | 不计入自动待删；停留「我的照片」（该页已于 2026-09-11 实装：`pages/PhotosPage`） |
| A3 | 到期物化 | 把时长改为 1 分钟并等待，重新打开 App 后照片出现在「待删除」，且**未**被删除 |
| A4 | 一键删除 | 待删除页一键删除后，沙箱中对应文件消失，RDB 记录状态为已删除 |
| A5 | 保留撤销 | 待删除页对某张点「保留」，该照片不再出现在待删除且文件仍在（**曾真机失败：`@State` 数组直传 native RDB 抛 401；根因已用真机 A/B 对照量出并修复**，见 `tasks/T04-trash-ui.md`「A5 缺陷定位与修复」） |
| A6 | 杀进程/重启 | 强制停止应用后重新打开，A3 结果一致（幂等，不重复计数） |
| A7 | 时钟回拨 | 系统时间往前调，不得把未到期照片误判为到期 |
| A8 | 相机被占用 | 其他应用占相机时，相机页给出可读错误而非崩溃 |
| A9 | 权限拒绝 | 拒绝相机权限后，页面引导去设置，不崩溃 |
| A10 | 存储写满 | 写入失败时不留半条 RDB 记录、不留孤儿文件 |

A1–A10 的可执行步骤在 [`T06`](../tasks/T06-e2e-acceptance.md) 展开。

## 附录 A：被否决的方案 —— Android APK 跑在卓易通

曾评估「用 Kotlin/MediaStore 写安卓应用，在卓易通里跑」：安卓侧 `MediaStore.createDeleteRequest` 能对任意相册资源发起带系统确认的删除，权限模型比鸿蒙宽松，工程上更省事。

否决理由：

1. **卓易通是容器而非系统**。它是基于 iSulad 的轻量安卓子系统，共享鸿蒙内核，且上架应用须与华为签协议；容器内应用的后台调度、媒体库映射、相机通路都存在已知的不一致报告（例如拍照存入系统相册失败、后台消息不推送）——恰好命中本项目的三个核心能力。
   [卓易通/出境易技术构成](https://cloud.tencent.cn/developer/article/2646600)、[卓易通应用拍照存入系统相册失败](https://bbs.itying.com/topic/6963cb2c6f4d61004c8394a8)。
2. **用户已选定原生路线**，且真机是 HarmonyOS 6.1，原生方案能真正控制相机 UI（勾选项必须在拍摄界面里）。
3. 原生方案在 D1 决策下**不需要任何受限权限**，安卓方案的优势（删别人照片）在本项目里并不需要。

保留为「如果 G0-A 彻底走不通」的最后退路；若启用，需重开 ADR 并重写 T03–T05。

## 附录 B：术语

| 术语 | 含义 |
|---|---|
| 惰性物化 | 不靠定时器，在任何一次 App 交互时按 `now` 重算到期状态 |
| 待删除 | 一个**状态**（PENDING_DELETE），不是一个物理目录 |
| 自有媒体仓 | 应用沙箱内的照片存储区，应用对其拥有完全删除权 |
| 命令登记表 | `docs/ENVIRONMENT.md` 中经真机验证的命令清单，脚本只能引用表内命令 |
