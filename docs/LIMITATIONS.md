# 已知限制（用户可见）
## 截屏最终结论（2026-09-11 真机收敛，推翻此前两版判断）

实测事实（本机 HUAWEI TGR-W10 / HarmonyOS 6.1.0.135）：

| 尝试 | 结果 |
|---|---|
| 前台 `screenshot.capture()`（已授权 `CUSTOM_SCREEN_CAPTURE`） | ✅ 调用成功（`Screenshot image 2800x1840`），但**画面就是本应用自己的界面**；用户进一步实测：**即使把应用置于悬浮窗，截出来依旧全是本应用**⇒ 该接口实际只给出**本应用窗口**内容 |
| 先 `moveAbilityToBackground()` 再 `capture()`（权限 `when:inuse`） | ❌ `201 Permission denied` |
| 同上，但把 `usedScene.when` 改为 **`always`** | ❌ 仍然 `201` ⇒ **系统只允许前台应用发起截屏**，与权限范围无关 |

**两条事实互相矛盾**：要截屏就必须在前台，而在前台屏幕上就必然有我们的界面 ⇒
**用 `capture()` 永远得不到"不含本页"的画面**。

因此最终方案（已落地）：
1. **「截屏含本页」= `window.snapshot()`**：无权限、任何设备可用，真机通过（截出来就是本应用页面）；
2. **「截屏不含本页」= 系统截屏 + 应用内「导入」**：系统截屏（电源+音量下 / 系统快捷开关，自带全屏与区域）
   时我们不在前台，**天然不含本页**；应用里点「截屏不含本页」会给出提示并**直接打开导入选择器**，一键纳管。
3. **撤回 `CUSTOM_SCREEN_CAPTURE` 权限声明**：它既达不到目的、又只在前台可用，留着只会增加权限面与审核成本。
   （此前基于同行文章认为"`capture()` 截不到自己"，真机实测否掉了这条 —— 再次印证：**文档/他人经验必须用真机复核**。）

## CUSTOM_SCREEN_CAPTURE 的申请经验（2026-09-11 调研，**修正此前判断**）

- 来源：同行实践记录 [鸿蒙截图工具开发实战 02](https://juejin.cn/post/7670111026742640650)（2026-08-05）、
  官方 [AVScreenCapture 录屏写文件](https://device.harmonyos.com/cn/docs/apiref/harmonyos-guides/using-avscreencapture-for-file)、
  [如何截取其他应用（Q&A）](https://bbs.itying.com/topic/692d05c12fcc650041be84b9)。
- ✅ **它不是"受限开放权限"，而是 `user_grant`（用户授权型）** —— 只需在 `module.json5` 声明
  （`reason` + `usedScene` 必填，弹窗与审核都会看），运行时 `requestPermissionsFromUser` 让用户点同意即可，
  **不需要 AGC 审批**。（此前我把它与 `WRITE_IMAGEVIDEO` 归为一类、说要 AGC 申请，是**错的**。）
- ✅ **API 14+，仅平板 / 2in1 开放** —— 本机正是平板（MatePad 11.5S / TGR-W10）+ API 24，**符合条件**。
- 经验要点：
  1. 查权限用 `checkAccessTokenSync`（静默、同步、不要求前台）；申请才用 `requestPermissionsFromUser`（**要求窗口在前台**）；
  2. 授权弹窗**只自动弹一次**，拒绝后必须留"去授权"入口（设置页状态行可点刷新）；
  3. **`screenshot.capture()` 有一条"不能截到自己"的约束** ⇒ 它天然满足我们「默认不含本软件页面」的要求！
- 由此得到的完整方案（**本期按用户要求不实现，接口先留存**）：
  「不含本页」= `CUSTOM_SCREEN_CAPTURE` + `screenshot.capture()`（能截整屏/区域，且截不到自己）；
  「含本页」= 现已实现的 `window.snapshot()`（无权限、任何设备可用）。两种模式都能有真实现。

## 内置截屏（2026-09-11 实测）

- SDK 有 `screenshot.pick()`（**无 @permission**，返回 `PickInfo{pickRect, pixelMap}`）——理论上可由用户在**系统框选界面**里授权并截图，区域+像素都拿到。
- **本机实测：不可用**。调用链正常（`native_screenshot_module.cpp AsyncGetScreenshot: Get Screenshot by picker`），
  但立即返回 `801 Capability not supported on this device`（801 在 d.ts 中的定义就是"设备不支持该能力"）。
  ⇒ 这台 HUAWEI TGR-W10 / HarmonyOS 6.1.0.135 不支持系统框选截屏。
- `screenshot.capture()` 需要受限权限 `ohos.permission.CUSTOM_SCREEN_CAPTURE`（同 `WRITE_IMAGEVIDEO` 一类），**不申请**。
- ✅ **「含本页」模式已用 `window.snapshot()` 实现并真机通过**：它只截**本应用自己的窗口**，
  d.ts 无 `@permission`、`@since 12` ⇒ **任何设备都能用**，是内置截屏的保底路径。
  真机证据：`shot done: ok=true self=true` → 列表 `1 张 · 共 138.8 KB`，缩略图就是本应用页面。
- 因此内置截屏的按钮保留（两种模式：默认**不含本页**=先退到后台再框选；可切**含本页**=窗口快照），
  在支持的设备上可用；本机走等价路径：**系统截屏（电源+音量下，自带区域/全屏，且截图时本应用不在前台、
  天然不含本页）→ 应用内「导入」（PhotoViewPicker）或直接分享到应用**。两条都免权限。

## 1. 本应用不管理、也不删除系统相册里的照片

- **为什么**：鸿蒙的三方应用删除系统相册资源需要受限开放权限 `ohos.permission.READ_IMAGEVIDEO` /
  `WRITE_IMAGEVIDEO`，官方只对克隆、备份、同步类场景开放；清理类场景申请基本不批。平台规则是「谁创建，谁管理」。
- **所以本项目怎么做**：自研相机把照片写进**应用自己的沙箱**，元数据存本地数据库，删除只操作自己的文件 ——
  零受限权限、零系统弹窗、删除必然成功。
- **代价**：这些照片**不会出现在系统图库**里；浏览与删除都在本应用内完成。

## 2. 截图不能被自动纳管

- **为什么**：截图由系统创建，不属于本应用，按第 1 条无法被自动接管或删除。
- **现状（已实现一条通路）**：截屏后，在系统的截屏预览/图库里点「**分享**」→ 选择「待删相机」，
  本应用会**复制一份**进自己的沙箱并纳入同一套状态机（`source = IMPORT`），之后按你设定的时长自动整理。
  实现走官方 Share Kit：`systemShare.getSharedData(want)` 解析 + `ohos.want.action.sendData` 声明。
- **仍未实现的一条通路**：应用内用 `PhotoViewPicker` 多选截图导入（T07-a），与上面二选一即可，暂未做。
- **两条通路共同的硬限制**：**原截图仍在系统图库，本应用无权删除**（`WRITE_IMAGEVIDEO` 是受限权限），
  必须由你自己去图库删。本应用不假装能做到这一点——结果页与本文都写明了。

## 3. 「到期自动」在你不打开应用时可能延迟

- **为什么**：`workScheduler` 延迟任务受应用活跃分组与系统配额约束（最小间隔按分组为 2h/4h/24h/48h 或禁止），
  **不保证准时**，也不保证一定被调用。
- **所以本项目怎么做**：正确性放在**惰性物化**上 —— 每次冷启、回前台、进入待删除页都会按当前时间重算到期状态，
  所以「到没到期」这件事永远是对的；调度与通知只用来**尽早**整理并提醒你。
- **对用户的含义**：可能你打开应用才看到照片已经进了待删除，这是设计取舍（换来的是被系统杀进程也不会出错）。

## 4. 删除是硬删，没有回收站

- **现状**：一期点「删除」即真正删除文件，不可恢复。
- **缓解**：删除前有二次确认，且确认文案会写明**张数与总体积**；「待删除」本身就是一个可见、可撤销的中间态
  （点「保留」即可移出）。
- **二期**：可加「最近删除」保留窗口。

## 5. 改设置不追溯已有照片

- **为什么**：每张照片在拍摄时就把当时的时长**快照**进记录（`policy_hours`），这样以后改默认时长不会
  让历史照片突然提前或被推迟到期。
- **对用户的含义**：设置页的「默认时长」只影响**之后**拍的/导入的照片。

## 6. 其他

- **通知**：若系统层面拒绝通知，应用只能引导你去设置页开启，无法绕过（`requestEnableNotification()` 被拒会返回
  `1600004` 且不再弹窗）。
- **鸿蒙 7 上的表现**：当前包可直接安装运行在 HarmonyOS 7（API 26）设备上；升级到 API 26 是可选优化，
  详见 [`HARMONYOS7-CHECKLIST.md`](HARMONYOS7-CHECKLIST.md)。
- **首次使用需要授予相机权限**：拒绝也能用（待删除页、设置页不受影响）。
