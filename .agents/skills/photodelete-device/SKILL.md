# PhotoDelete 真机回路

## 一次完整的真机回路

```
构建 → 签名 → 装机 → 拉起 → 抓日志 → 判据 → 清理（force-stop）
```

- 具体命令**只取** `docs/ENVIRONMENT.md` 命令登记表中 ✅ 的行；表里没有的写法，先在 T00 里验证并登记。
- 构建、装机、`hilog` 全部用**后台 job**；别为等结果空转，同时去推进不依赖设备的工作。
- `hilog` 抓够证据就 `job_kill`，不要留常驻任务。

## G0-B：相机落盘探针（T00 的核心未知数）

目的：定死「`photoOutput` 出图后，字节流如何落到应用沙箱」这条路，写进 ADR-001。按顺序试，**第一个跑通的即为选定方案**：

| 方案 | 做法 | 判定 |
|---|---|---|
| A（首选） | `photoOutput.on('photoAvailable')` 拿 `image.Image` → `ImagePacker.packing` 成 JPEG → `fileIo` 写沙箱 | 沙箱里出现字节正确、可被 `<Image>` 渲染的文件，且**未申请任何媒体库权限** |
| B | `photoOutput.capture()` 默认落盘 + 查询自有媒体资源 | 是否要求 `WRITE_IMAGEVIDEO`：要 → B 直接淘汰 |
| C | 安全控件 `SaveButton` 导出到系统相册 | 仅用于二期「保留/导出」，不作为主路径 |

探针要记录：可用性（可用/不可用/要权限）、实际代码路径、返回类型、真机型号与系统版本、失败时的错误码原文。结论写入 `docs/decisions/ADR-001-camera-capture-path.md`。

## 端到端验收要点（对应 PLAN.md §4）

- **A3 到期物化**：把默认时长改成 1 分钟 → 拍摄 → 等过 1 分钟 → 冷启应用 → 照片应出现在「待删除」且**未被删除**。
- **A6 杀进程/重启**：`aa force-stop` 后重新拉起，结果必须与 A3 一致（幂等）。
- **A7 时钟回拨**：把系统时间往前调，未到期照片**不得**被判为到期；测完把时间调回。
- **A8/A9**：相机被占用、拒绝权限 —— 记录实际错误文案，确认是可控提示而非崩溃。
- **A10**：可用 `hdc shell` 把沙箱目录塞满或写只读来构造失败，确认不留孤儿文件与半条记录。

## 纪律

1. 报告必须给**真实命令 + 真实输出片段**；「应该能跑」不算证据。
2. 失败先保留现场（日志、错误码、文件列表），再改代码；不要靠重启应用碰运气。
3. 涉及用户数据的操作（一键删除）在真机上要**先确认这些照片确实可丢**，测试图用临时拍摄的内容。
4. 不动系统相册：本项目只在应用沙箱内操作（硬约束 2）。
